# AX 기반 업무 운영 체계 기획안 (최종본)

> AI Transformation(AX) 시대, 조직의 생산성을 측정·운영·개선하기 위한 통합 프레임워크

---

## 1. 배경 및 목적

AI가 단순 도구를 넘어 실제 업무를 수행하는 주체가 되면서, 인간의 역할은 점차 **AI 업무의 감독자·피드백 제공자**로 전환되고 있다. 이를 효과적으로 운영·측정하려면 기존의 인간 중심 KPI가 아닌 **AX 전용 KPI 체계와 실시간 모니터링 인프라**가 필요하다.

본 기획안은 다음을 목표로 한다.

1. AX 수준을 정량 측정하는 KPI 체계 수립
2. AI 작업의 **성공 확률** 관리와 체계적 개선 루프 구축
3. 백로그 기반 인력·비용·세션 자동 산정 모델
4. 그래프 네트워크 기반 실시간 모니터링 시스템

---

## 2. 핵심 통찰

> **"AI가 할 수 있다"** 와 **"AI가 안정적으로 해낸다"** 는 다른 차원의 문제다.

AX의 성숙도는 다음 세 축의 곱으로 결정된다.

```
AX 종합 지수 = AI 수행 비율 × 작업 성공률 × (1 / 단위 비용)
```

- **Coverage** — 얼마나 많은 일을 AI에게 맡길 수 있는가
- **Success** — 그 일들을 얼마나 잘 해내는가
- **Cost** — 그것을 얼마의 비용으로 해내는가

세 축 모두를 동시에 측정·관리하지 않으면 AX의 실질적 가치를 판단할 수 없다.

---

## 3. KPI 체계

### 3.1 AX 수준 측정 KPI (Coverage)

| KPI | 정의 | 단위 |
|---|---|---|
| AI 수행 비율 | 전체 업무 중 AI가 수행하는 비중 | % |
| AI 자율 수행 시간 | 인간 개입 없이 단독 수행한 평균 시간 | 분/시간 |
| 개입 빈도 | 단위 업무 완료까지 필요한 인간 개입 횟수 | 회 |
| 세션당 토큰 비용 | 업무 단위당 AI 운영 비용 | KRW |

### 3.2 작업 성공률 KPI (Success)

| KPI | 정의 | 단위 |
|---|---|---|
| 작업 성공률 | 인간 기준 충족하며 완료한 비율 | % |
| 첫 시도 성공률 | 재시도·개입 없이 한 번에 완료한 비율 | % |
| 재시도 횟수 | 성공까지 소요된 평균 시도 횟수 | 회 |
| 품질 등급 분포 | 우수 / 허용 / 재작업 / 실패 비율 | % |
| 실패 회복률 | 개입 후 성공 전환된 비율 | % |

**성공의 정의 (작업 유형별 차등 적용)**

- **결정론적 작업** (코드 실행, 데이터 변환) → 자동 검증 통과 여부
- **생성형 작업** (문서, 기획, 디자인) → 인간 평가 또는 LLM-as-Judge 점수
- **의사결정 작업** (분류, 추천) → 정답 데이터 대비 정확도
- **에이전트 작업** (다단계 수행) → 최종 목표 달성 여부 + 중간 단계 통과율

### 3.3 인간 생산성 KPI (Capacity)

| KPI | 정의 | 단위 |
|---|---|---|
| 동시 세션 처리 수 | 1인이 무중단 관리 가능한 AI 세션 수 | 개 |
| 개입 응답 시간 | 개입 요청 후 응답까지의 시간 | 초 |
| 피드백 효과도 | 개입이 후속 수행에 미친 개선도 | Δ% |

## 4. 성공률 측정 방식

### 4.1 계층적 측정 구조

```
프로젝트 (Project)         ← 비즈니스 목표 달성률
   └ 프로세스 (Process)    ← end-to-end 성공률
       └ 작업 (Atomic)     ← raw 성공률
```

체인이 길어질수록 누적 성공률이 급격히 떨어진다.
**예: 단계별 90% × 5단계 = 59%** → 프로세스 단위 측정이 핵심이다.

### 4.2 데이터 수집 항목

- **개입 사유 태깅**: 오류 수정 / 품질 개선 / 방향 전환 / 안전 검토
- **품질 평가 로그**: rubric 기반 점수
- **실패 원인 분류**: 프롬프트 문제 / 컨텍스트 부족 / 모델 한계 / 외부 시스템 오류

---

## 5. 개선 루프 (Improvement Loop)

성공률은 측정만으로 오르지 않는다. 4단계 사이클을 정착시킨다.

### ① 진단 (Diagnose)
- 임계치 미달 작업 자동 식별
- 실패 패턴 클러스터링
- 개입 사유 분석으로 근본 원인 파악

### ② 개선안 도출 (Design)
- **프롬프트 개선**: 지시 명확화, few-shot 예시 추가
- **컨텍스트 보강**: 참조 문서·도메인 지식·과거 산출물 주입
- **워크플로 재설계**: 작업 분할, 검증 단계 삽입, 체크포인트 추가
- **모델 교체·튜닝**: 적합 모델 선택, 파인튜닝 검토
- **휴먼 게이트**: 실패 비용이 큰 단계에 인간 검토 의무화

### ③ 실험 (Experiment)
- A/B 테스트로 검증 (기존 vs 개선 병렬 운영)
- 골든 데이터셋으로 회귀 테스트
- 섀도우 운영 후 전환

### ④ 적용 및 학습 (Deploy & Learn)
- 검증된 개선안을 표준 워크플로에 반영
- 실패 사례를 **조직 지식베이스**로 축적
- 모니터에 개선 이력 표시 (변경 → 성공률 증감)

## 6. 자원 산정 모델

### 6.1 백로그 → 인력·비용 자동 산정

```
1. 백로그 도출       프로젝트 전체를 단위 작업으로 분해
2. 역량 매핑          난이도를 주니어/시니어/전문가로 분류
3. 세션 추정          작업당 평균 동시 세션 수 산정
4. 인력 산정          필요 인력 = Σ(작업별 세션 수) ÷ 1인당 동시 처리 가능 세션 수
5. 비용 산정          총 비용 = 인건비 + 토큰 비용 + 인프라 비용
```

백로그 갱신 시마다 인력·비용을 자동 재계산하여 프로젝트 리스크를 조기 가시화한다.

### 6.2 성공률 기반 의사결정

- **자동화 vs 인간 수행**: 성공률 낮고 개선 어려우면 인간 위임
- **휴먼 게이트 위치**: 누적 성공률 급락 구간 앞에 검증 단계 배치
- **세션 할당 우선순위**: 성공률 낮은 작업은 시니어 우선 배정
- **ROI 산정**: `성공률 × 가치 ÷ 토큰 비용` 기준 작업 평가

## 7. 실시간 모니터링 시스템

### 7.1 시스템 개요

백로그를 프로세스 단계로 분해하고, 각 단계의 입력·출력·자원 사용을 **그래프 네트워크**로 추적한다.

### 7.2 주요 기능

- **그래프 네트워크 뷰** — 업무 흐름을 노드(단계)와 엣지(연결)로 시각화
- **노드 상세 패널** — 입력/출력 산출물, AI 수행 시간, 토큰, 인간 개입 이력
- **진척·자원 대시보드** — 완료율, 병목 구간, 인력 워크로드
- **개입 라우팅** — AI의 개입 요청 시 적합 담당자에게 자동 라우팅

### 7.3 대시보드 4대 화면

1. **전체 AX 수준 요약** — Coverage / Success / Cost 종합
2. **프로젝트 진척** — 그래프 네트워크 뷰
3. **인력 워크로드** — 세션 처리 현황
4. **비용 현황** — 토큰·인건비 추이

### 7.4 시각 인코딩

- **노드 색상**: 성공률을 색으로 표시 (녹색=안정, 황색=주의, 적색=위험)
- **노드 크기**: 토큰 사용량 또는 처리량 비례
- **엣지 굵기**: 작업 흐름량 비례
- **펄스 애니메이션**: 현재 활성 작업 표시
- **드릴다운**: 노드 클릭 시 추이·실패 사례·개선 이력 표시

## 8. 도입 로드맵

| Phase | 기간 | 주요 산출물 |
|---|---|---|
| 1. KPI 체계 수립 | 1~2개월 | KPI 정의서, 베이스라인 측정 |
| 2. 모니터링 MVP | 3~4개월 | 백로그 연동, 그래프 시각화 프로토타입 |
| 3. 성공률 개선 루프 | 5~6개월 | 개선 실험 플랫폼, 지식베이스 |
| 4. 자동화·확산 | 7~9개월 | 인력·비용 자동 산정, 전사 확산 |

## 9. 기대 효과

- **가시성** — AX 수준의 정량 측정으로 경영 의사결정 근거 확보
- **예측성** — 백로그 기반 인력·비용 산정으로 리스크 감소
- **품질** — 성공률 KPI와 개선 루프로 AI 산출물 신뢰도 향상
- **생산성** — 동시 세션 운영 최적화로 동일 인력 대비 처리량 증대
- **확장성** — 표준화된 KPI·모니터링으로 전사 AX 확산 기반 마련
