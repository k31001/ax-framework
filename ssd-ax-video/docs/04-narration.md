# 나레이션 대본

> 상태: 승인본 (2026-11-11)
> 음성: ElevenLabs 라이브러리의 한국어 여성 음성 Sola, 모델 `eleven_multilingual_v2`. 화면 자막은 지금처럼 짧은 명사형으로 두고, 나레이션은 말로 듣기 좋은 문장으로 쓴다.

## 원칙

- **말하는 문장.** "-습니다" 체. 한 문장은 한 호흡(25음절 안팎).
- **화면을 따라간다.** 각 문장은 그 내용이 화면에 나타나는 순간에 시작한다. 나레이션이 길면 화면이 기다린다(뒤 항목의 등장 시점을 늦추고 씬을 늘린다).
- **화면 글자를 그대로 읽지 않는다.** 자막이 이름을 붙이고, 나레이션은 뜻을 풀어 준다.
- **수치는 출처가 화면에 있는 것만** 말한다.
- 영문 기술 용어는 현업 발음으로 읽힌다(regression, assertion, FW 등). 합성 뒤 발음이 어색한 단어는 한글 표기로 바꿔 다시 만든다.

## 대본

괄호 안은 그 문장이 맞춰 시작하는 화면 항목이다.

### S1 Hook
1. 우리는 이미 AI를 쓰고 있습니다. (자막 1)
2. 코드 초안, 로그 요약, 스크립트. (자막 2)
3. 손 닿는 열매는 꽤 땄습니다. (자막 3)

### S2 문제
1. 개인은 빨라졌어도, 과제 일정은 그대로입니다. (자막 1)
2. 작성이 빨라지면, 병목은 검증과 통합으로 옮겨갈 뿐입니다. (자막 2)
3. 칩 개발 공수의 60에서 70%가 검증입니다. (수치)

### S3 전환 선언
1. AI 도입을 넘어서, (도입 문구)
2. AI를 중심으로 일을 다시 설계해야 합니다. (핵심 문구)
3. 작업 보조에서 워크플로 에이전트로, 그리고 프로세스 재설계로. (3단계)

### S4 사례 소개
1. 요구사항 하나를 따라가 보겠습니다. (제목)
2. 수명 말기 NAND에서도 read 지연을 지키는 것. (요구사항 카드)
3. 복구 단계가 깊어질수록, 지연은 길어집니다. (복구 3단계)

### S4J Jira 추적
1. 이 요구사항은, Jira의 이슈입니다. (카드의 JIRA 표시와 키)
2. 요구사항에서 설계 기능, 검증 항목, 버그까지, 링크로 이어집니다. (추적 사슬)
3. 사람도 에이전트도, 여기서 현황을 읽고, (보드와 JQL)
4. 업무 지시와 새 요구사항도, 여기에 남깁니다. (댓글과 새 이슈)

### S5-1 요구사항 분석
1. 지금은 문서를 사람이 대조해서, 충돌을 늦게 발견합니다. (현재)
2. 에이전트가 조항을 추출해 충돌 위험을 먼저 찾고, (에이전트)
3. 사람은 우선순위와 수용 기준을 정합니다. (사람)

### S5-2 아키텍처 설계
1. 요구사항이 크게 바뀌면, 이전 구조를 그대로 쓸 수 없습니다. (배경 문구. 바뀐 것의 표와 이전 구조)
2. RTL부터 짜면, 구조의 문제는 emulation에서야 드러납니다. (현재)
3. 그래서 에이전트가 목적별 모델로, 수백 개 구성을 여러 관점에서 탐색하고, (에이전트)
4. 사람이 오류 복구를 HW로 옮기는 안을 고릅니다. (사람)
5. 그런데 구조 검증에서, GC 중에 지연 기준을 넘는 문제가 드러납니다. (문제)
6. host read 우선 큐를 더해 해결합니다. RTL을 쓰기도 전에요. (해결)

### S5-3 IP 설계 · PPA
1. RTL 설계자는 블록도 한 장 대신, 블록별 예산과 계약을 받습니다. (배경 문구. 지연 예산 막대와 interface 계약)
2. API 문서로 남던 동작 규약을, 실행 가능한 계약으로 정의합니다. (사람)
3. 에이전트는 그 계약에서 RTL을 생성하고, (에이전트)
4. 면적이 예산을 넘으면, 축소안을 구조 모델로 다시 확인합니다. (문제)
5. 예산을 지키는 방법은, 설계자가 정합니다. (강조 문구)
6. 스펙이 원본이 됩니다. (원칙)

### S5-4 시뮬레이션 검증
1. 통과 기준은 사람이, 테스트벤치는 에이전트가 만듭니다. (사람)
2. 밤사이 실패가 312건. (문제)
3. 에이전트가 원인을 넷으로 묶고, (에이전트: 분류)
4. 완료 신호 누락이라는 가설을, Jira 버그로 올립니다. (에이전트: 가설. 항목에 `BUG-2268` 과 `ai-authored`)
5. 사람이 승인하면, assertion을 더해 다시 검증합니다. (사람)
6. 루프를 닫으면, 같은 모델의 디버깅 통과율이 44에서 94%로 오릅니다. (원칙)

### S5-5 Emulation · FPGA
1. 장비가 준비되기 전에는 가상 플랫폼에서 먼저 통합하고, 이후엔 매일 함께 돌립니다. (에이전트)
2. 장시간 부하에서 멈춤이 생기자, (문제)
3. 에이전트가 파형과 trace를 겹쳐 보고, interrupt 한 건의 유실을 찾습니다. (에이전트)
4. HW와 FW가 함께, 완료 전달을 큐 방식으로 바꿉니다. (사람)

### S5-6 FW 개발
1. 정정에 실패한 데이터는 내보내지 않는다. 이런 불변식은 사람이 정의하고, (사람)
2. 에이전트는 가상 플랫폼과 보드에서 빌드와 수정을 반복합니다. (에이전트)
3. read retry table은 실제 NAND로 사람이 승인합니다. (사람)

### S5-7 제품 테스트 · 퀄
1. 고온 방치 후, 특정 lot에서 지연 기준을 넘었습니다. (문제)
2. 에이전트가 신규 불량 후보와 수정안을 내고, (에이전트)
3. 처분과 재시험 범위는 사람이 정합니다. (사람)
4. 시험 시간은 줄지 않습니다. 줄어드는 건 원인 분석과 증빙 취합입니다. (강조 문구)
5. 퀄 패키지는 에이전트가 조립하고, 판정과 서명은 사람이 합니다. (에이전트, 사람)
6. 필드 데이터는, Jira의 새 요구사항으로 돌아옵니다. (마무리. 문구 옆에 `REQ-231`)

### S6 5대 전환
1. 정리하면, 다섯 가지가 바뀝니다. (제목)
2. 문서는 실행 가능한 스펙으로. (1행)
3. 순차 handoff는 상시 루프로. (2행)
4. 직접 작성에서, 의도 정의와 증거 기반 판단으로. (3행)
5. 개인 챗봇은 통합 플랫폼으로. (4행)
6. 개인의 요령은 팀의 학습으로. (5행)

### S7 책임
1. 작업은 자동화해도, 책임은 사람에게 있습니다. (핵심 문구)
2. 한 실험에서 AI는 검증 완료를 선언했지만, 심어 둔 버그의 21%를 놓쳤습니다. (수치)

### S8 로드맵
1. 순서는 세 단계입니다. (제목)
2. 기반을 깔고, 병목부터 에이전트에게 맡기고, 프로세스를 다시 그립니다. (3단계)
3. 얻은 성과는 다음 단계에 재투자합니다. (마무리)

### S9 Closing
1. 설계, 검증, FW, 테스트와 퀄. (역할 네 줄)
2. 모두 작성하는 사람에서, 설계하는 사람으로 바뀝니다. (작성자에서 설계자로)
3. AI 중심 재설계. (핵심 문구)
4. 우리 팀의 다음 단계입니다. (엔드 카드)

## 만드는 법

0. 문장을 더하거나 뺄 때는 `src/video/content.ts` 의 beat와 `audio/retime.py` 의 대응 표(문구, 기준 시점, 문장 번호)를 같이 맞춘다. 문장이 끝나기 전에 화면이 바뀌는 항목(본문 전체를 쓰는 배경 그림 등)에는 표의 넷째 값으로 쉼을 더 준다.
1. `python3 audio/narration.py` — 문장별 음성을 `public/audio/narration/` 에 만든다. 읽히는 문장(발음을 위해 영문 약어와 숫자를 한글로 적은 것)은 이 스크립트에 있다. 문장을 고치면 그 씬만 다시 만든다(`python3 audio/narration.py S5-4`).
2. `python3 audio/retime.py` — 음성 길이에 맞춰 `content.ts` 의 등장 시점과 `timeline.ts` 의 씬 길이를 고치고, 문장별 시작 시점을 `src/video/narration.ts` 에 쓴다.
3. 씬 길이가 바뀌었으면 `audio/make_bgm.py` 의 구간 표를 고치고 배경음악을 다시 만든다.

## 길이 (초안 때의 추정)

전체 약 1,300자. 음성은 1초에 약 5.7음절로 읽힌다(샘플 실측). 지금 씬 길이에 다 들어가지 않는 곳(S5-4, S5-5, S5-7, S6, S7 등)은 그 씬의 항목 등장 시점을 나레이션에 맞춰 늦추고 씬을 늘린다. 예상 전체 길이는 **약 3분 20초**(지금 3분 7초). 배경음악은 새 씬 길이에 맞춰 다시 만들고, 나레이션이 나오는 동안 음량을 낮춘다.

실제 결과: 음성 226초, 영상 전체 **4분 50초**(290초).

Jira 추적 반영(2026-11-11): S4J 네 문장을 더하고 S5-4, S5-7의 한 문장씩을 바꿔 그 세 씬을 다시 합성했다. 음성 243초, 영상 전체 **5분 11초**(311초). "Jira"는 "지라"로 읽힌다.

구조 설계 반영(2026-11-12): S5-2에 두 문장을 더하고 한 문장을 바꿨다. S5-3에 두 문장을 더했다. 두 씬을 다시 합성했다. S5-2는 25초에서 35.5초로, S5-3은 20.5초에서 31.5초로 늘었다. 음성 264초, 영상 전체 **5분 32초**(332.5초). 이 주제를 깊게 다룬 별도 영상의 근거는 `06-architecture-exploration.md` 에 있다.
