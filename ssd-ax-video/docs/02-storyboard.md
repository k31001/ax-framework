## 3. 씬별 대본

자막은 화면에 나오는 문구 그대로다. 화면 설명은 디자인 안이 정해지면 그 스타일에 맞춰 구체화한다.

### S1 Hook (12초)

| 자막 | 화면 |
|---|---|
| 우리는 이미 AI를 쓰고 있습니다. | 엔지니어 책상 위의 작은 장면들이 하나씩 켜진다 |
| 코드 초안. 로그 요약. 스크립트. | 세 가지 작업이 각각 짧게 완료된다 |
| 손 닿는 열매는 꽤 땄습니다. | 낮은 가지의 열매 몇 개가 사라지고, 나무 전체는 그대로 남는다 |

### S2 문제 (20초)

| 자막 | 화면 |
|---|---|
| 개인은 빨라졌습니다. | 7단계 흐름 위에서 점 몇 개가 빠르게 깜빡인다 |
| 그런데 과제 일정은 그대로입니다. | 전체 흐름의 길이는 줄지 않는다 |
| 작성이 빨라지면, 병목은 다음 단계로 옮겨갑니다. | 앞 단계에서 쏟아진 작업이 검증과 통합 앞에 쌓인다 |
| 칩 프로젝트 엔지니어링 노력의 60~70%는 검증 | 수치 강조. 출처: Siemens EDA, 2025 |
| 빨라진 것은 작성. 막히는 곳은 흐름. | 쌓인 대기열에 시선이 모인다 |

### S3 전환 선언 (16초)

| 자막 | 화면 |
|---|---|
| AI를 지금의 일에 끼워 넣는 것만으로는 부족합니다. | 기존 흐름 위에 덧붙인 조각들이 흐려진다 |
| **AI를 전제로, 일을 다시 설계한다** | 화면이 비워지고 핵심 메시지가 크게 나온다 |
| 작업 보조 → 워크플로 에이전트 → 프로세스 재설계 | 3단계 계단. 첫 단에 "지금 우리는 여기" 표시 |

### S4 다섯 가지 전환 (25초)

제목 자막: **다섯 가지를 바꿉니다**

| 축 | 지금 | 지향점 |
|---|---|---|
| 산출물 | 사람이 읽는 문서 | 기계가 읽고 실행하는 스펙 |
| 프로세스 | 순차 handoff | gate 사이를 메우는 상시 루프 |
| 일하는 방식 | 직접 작성 | 의도를 정하고 증거로 판단 |
| 시스템 | 각자의 챗봇 | 툴과 데이터가 연결된 AI 플랫폼 |
| 문화 | 개인의 요령 | 측정하고 공유하고 학습하는 팀 |

축마다 약 4.5초. "지금"이 먼저 나오고 "지향점"으로 바뀐다. 다섯 축이 끝나면 한 화면에 모인다.

### S5 전 과정 여정 (60초)

제목 자막: **요구사항에서 퀄까지**

화면 위쪽에 7단계 진행 표시가 계속 떠 있고, 현재 단계가 강조된다. 단계마다 약 8초. "지금"을 먼저 보여 주고 "바뀐 뒤"로 전환한다.

| # | 단계 | 지금 | 바뀐 뒤 |
|---|---|---|---|
| 1 | 요구사항 분석 | PDF와 엑셀을 눈으로 대조 | 한 줄을 고치면 영향받는 블록과 테스트가 켜진다 |
| 2 | 아키텍처 설계 | 회의로 고르는 블록도 세 안 | 수백 개 후보 중에서 최적점을 고른다 |
| 3 | IP 설계 · PPA | 스펙 옆에서 RTL을 타이핑 | 스펙에서 RTL·헤더·assertion이 함께 나오고, PPA는 commit마다 돌아온다 |
| 4 | 시뮬레이션 검증 | 아침마다 regression 실패를 분류 | 밤새 도는 루프가 원인 가설이 붙은 티켓만 남긴다 |
| 5 | Emulation · FPGA | 장비 대기열. 뒤늦게 만나는 HW와 FW | 첫 commit부터 실제 FW가 매일 부팅된다 |
| 6 | FW 개발 | 스펙을 손으로 옮기며 실리콘을 기다린다 | 같은 스펙에서 driver와 테스트가 나온다 |
| 7 | 제품 테스트 · 퀄 | 로그 더미. 막바지의 증빙 취합 | 새로운 불량만 사람에게. 증빙은 개발 내내 쌓인다 |

마지막 자막: **필드에서 배운 것은 다시 요구사항으로.** 7단계 끝에서 선이 1단계로 돌아가 고리가 닫힌다.

### S6 세 가지 원칙 (14초)

제목 자막: **이것을 가능하게 하는 세 가지**

| 자막 | 화면 |
|---|---|
| 스펙이 원본이 된다 | 스펙 하나에서 여러 산출물이 갈라져 나온다 |
| 루프를 닫는다 | 실행 → 결과 → 수정이 원을 그리며 돈다 |
| 같은 모델, 디버깅 통과율 44% → 94% | 수치 강조. 출처: NVIDIA 자체 평가, 2026 (모델 단독 → 에이전트 루프) |
| 하나의 실로 잇는다 | 요구사항부터 퀄 증빙까지 한 줄로 꿰인다 |

### S7 책임 (12초)

| 자막 | 화면 |
|---|---|
| 그리고 하나는 바꾸지 않습니다. | 화면이 차분해진다 |
| 책임은 사람에게. | gate 앞에 사람이 선다 |
| 심어 둔 bug 806개. AI는 완료를 선언했지만, 가장 좋은 모델도 5개 중 1개를 놓쳤습니다. | 수치 강조. 출처: SemiEngineering, 2026-11 |
| 검증하는 일은 자동화해도, 책임은 자동화하지 않는다. | 문장만 남는다 |

### S8 로드맵 (14초)

제목 자막: **세 걸음**

| 걸음 | 자막 |
|---|---|
| 1 | 기반을 깐다: 플랫폼 · 데이터 · 기준선 |
| 2 | 병목부터 에이전트에게: 워크플로 단위의 닫힌 루프 |
| 3 | 프로세스를 다시 그린다: 스펙 중심의 흐름, 새로운 역할 |

마지막 자막: **딴 열매는 다음 걸음의 씨앗으로.** S1의 열매가 다시 나와 첫 걸음 아래에 심긴다.

### S9 Closing (9초)

| 자막 | 화면 |
|---|---|
| 우리의 자리는 작성자에서 설계자로. | 사람이 흐름 전체를 내려다보는 자리로 옮겨간다 |
| **AI를 전제로, 일을 다시 설계한다** | 핵심 메시지 |
| SSD Controller SoC · AX Strategy | 엔드 카드 |

## 4. 영상에 넣는 수치

세 개 모두 2026-11-10에 원문을 직접 확인했다.

| 씬 | 화면 문구 | 원문 내용 | 출처 |
|---|---|---|---|
| S2 | 칩 프로젝트 엔지니어링 노력의 60~70%는 검증 | "60–70% of engineering effort in chip projects belongs in verification" | Siemens EDA 블로그 (Harry Foster), 2025-09-03 |
| S6 | 같은 모델, 디버깅 통과율 44% → 94% | CVDP 디버깅 항목에서 한 모델이 단독 44.0%, 에이전트와 함께 94.3% | NVIDIA Technical Blog, 2026-07-26 (자체 평가) |
| S7 | bug 806개, 가장 좋은 모델도 5개 중 1개를 놓침 | 설계 25개에 bug 806개를 심었고 최고 모델이 20.8%를 누락. 세 모델 모두 자체 목표 100% 달성 후 sign-off 선언 | SemiEngineering, 2026-11-02 |

S7의 마지막 문장은 같은 기사에 인용된 Arm 소속 엔지니어의 말("You can automate the work of verification. You cannot automate the responsibility for it.")을 옮긴 것이다.
