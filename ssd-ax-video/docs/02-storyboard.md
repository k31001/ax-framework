## 2. 자막 문체 원칙

- **명사형으로 끝낸다.** "다시 설계한다"가 아니라 "재설계". 서술형 어미(-습니다, -한다)를 쓰지 않는다.
- **한자어를 한글로 쓴다.** 재설계, 수작업, 대조, 취합, 축적, 상시, 공수. 뜻이 바로 오지 않는 어려운 한자어는 피한다.
- **기술 용어는 영어 그대로.** RTL, PPA, regression, commit, FW, driver, assertion, handoff, interrupt.
- **한 번에 문구 하나.** 설명은 화면이 하고, 자막은 이름만 붙인다.

## 4. 사례 구간의 화면 문법

S5의 일곱 씬은 같은 구성을 쓴다. 보는 사람이 두 번째 단계부터는 읽는 법을 알고 있게 한다.

- **요구사항 카드.** REQ-QOS-07 카드가 화면 위쪽의 7단계 표시를 따라 이동한다. 단계가 끝날 때마다 그 단계의 기록이 카드에 하나씩 붙는다.
- **두 줄 구성.** 화면을 "에이전트" 줄과 "사람" 줄로 나눈다. 일이 일어나는 순서대로 각 줄에 항목이 나타나 흐름도가 완성된다. 누가 무엇을 하는지가 한눈에 보인다.
- **현재 → 전환 후.** 단계가 시작되면 "현재" 한 줄이 먼저 나오고, 흐려지면서 "전환 후" 흐름으로 바뀐다.
- **문제와 해결.** 문제는 경고색 표식으로 흐름 중간에 나타나고, 해결되면 표식이 풀린다.

## 5. 씬별 대본

자막은 화면에 나오는 문구 그대로다. 화면 설명은 디자인 안이 정해지면 그 스타일에 맞춰 구체화한다.

### S1 Hook (10초)

| 자막 | 화면 |
|---|---|
| AI 활용, 이미 일상 | 엔지니어 책상 위의 작은 장면들이 하나씩 켜진다 |
| 코드 초안 · 로그 요약 · 스크립트 | 세 가지 작업이 각각 짧게 완료된다 |
| 쉬운 열매는 수확 완료 | 낮은 가지의 열매 몇 개가 사라지고, 나무 전체는 그대로 남는다 |

### S2 문제 (15초)

| 자막 | 화면 |
|---|---|
| 개인 속도 향상, 과제 일정은 제자리 | 7단계 흐름 위에서 점 몇 개가 빠르게 깜빡이지만 전체 길이는 줄지 않는다 |
| 작성 가속 → 병목 이동 | 앞 단계에서 쏟아진 작업이 검증과 통합 앞에 쌓인다 |
| 칩 개발 공수의 60~70%는 검증 | 수치 강조. 출처: Siemens EDA, 2025 |

### S3 전환 선언 (12초)

| 자막 | 화면 |
|---|---|
| AI 도입을 넘어 | 기존 흐름 위에 덧붙인 조각들이 흐려진다 |
| **AI 중심 재설계** | 화면이 비워지고 핵심 메시지가 크게 나온다 |
| 작업 보조 → 워크플로 에이전트 → 프로세스 재설계 | 3단계 계단. 첫 단에 "현재" 표시 |

### S4 사례 소개 (14초)

| 자막 | 화면 |
|---|---|
| **요구사항 하나의 여정** | 제목 |
| 차세대 데이터센터 SSD 컨트롤러 · 신세대 QLC NAND | 과제 설정 |
| REQ-QOS-07 · 수명 말기 read 지연 보장 · P99.99 ≤ 2 ms (예시) | 요구사항 카드가 만들어진다 |
| read retry → soft decoding → parity 복구: 단계가 깊을수록 지연 증가 | 오류 복구 단계가 차례로 내려가며 지연 막대가 길어진다 |
| 요구사항부터 퀄까지 | 카드 앞에 7단계 길이 펼쳐진다 |

### S5-1 요구사항 분석 (18초)

| 구분 | 자막 |
|---|---|
| 현재 | 문서 수작업 대조, 충돌은 뒤늦게 발견 |
| 에이전트 | 조항 단위 추출 · 요구사항 그래프 등록 |
| 에이전트 | 충돌 위험 탐지: QLC 오류율 ↔ read 지연 |
| 에이전트 | 모호한 조항 질의: 혼합 부하 조건 누락 |
| 사람 | 우선순위 결정 · 수용 기준 확정 |
| 카드에 추가 | 출처 조항 · 수용 기준 · 영향 블록 |

화면: 고객 요구서, NAND 스펙, 표준 세 문서가 조항 단위로 쪼개져 그래프의 점이 된다. 두 점 사이에 충돌 표식이 켜진다.

### S5-2 아키텍처 설계 (22초)

| 구분 | 자막 |
|---|---|
| 현재 | 소수 후보, 회의로 결정 |
| 사람 | 목표 · 제약 설정 |
| 에이전트 | 보정된 성능 모델로 수백 구성 탐색 |
| 사람 | 선택: 오류 복구 제어를 FW에서 HW로 |
| 문제 | 구조 검증: GC 중 soft decoding 요청 집중, P99.99 초과 |
| 해결 | host read 우선 큐 추가 · 재실행 통과 |
| 강조 | RTL 작성 전 발견 |
| 카드에 추가 | 구조 모델 · 결정 기록 · 블록별 예산 |

화면: 지연·면적·전력 좌표에 후보 점 수백 개가 찍히고 사람이 하나를 고른다. 고른 구조에서 GC read와 host read가 soft decoder 앞에 줄을 서고, 우선 큐가 생기면서 host read가 앞으로 나온다.

### S5-3 IP 설계 · PPA (20초)

| 구분 | 자막 |
|---|---|
| 현재 | 구조 문서 해석 후 RTL 작성, 동작 규약은 문서로 전달 |
| 사람 | interface 계약 · microarchitecture 확정 |
| 에이전트 | 스펙에서 register RTL · FW 헤더 생성 |
| 에이전트 | 제어 블록 RTL 생성, lint · CDC · sim · formal 반복 |
| 에이전트 | commit마다 PPA 추정 |
| 문제 | ECC 블록 면적 예산 초과 |
| 해결 | soft decoder 축소안 · 구조 모델로 지연 재확인 · 사람 승인 |
| 원칙 표식 | **스펙 원본화** |

화면: 스펙 하나에서 RTL, FW 헤더, 검증 모델이 갈라져 나온다. Commit이 쌓일 때마다 면적 막대가 갱신되다가 예산선을 넘는다. 화살표가 S5-2의 구조 모델로 되돌아갔다 온다.

### S5-4 시뮬레이션 검증 (22초)

| 구분 | 자막 |
|---|---|
| 현재 | 실패 수백 건, 원인 분석은 수작업 |
| 사람 | 통과 기준 정의 · reference model 소유 |
| 에이전트 | 블록별 수용 기준에서 testplan · testbench 생성 |
| 문제 | 야간 regression 실패 312건 |
| 에이전트 | 원인 4개로 분류 · 대표 seed 재실행 |
| 에이전트 | 원인 가설: 복구 요청과 완료 신호의 동시 도착, FSM의 완료 누락 |
| 사람 | 가설 확인 · 수정 승인 |
| 해결 | assertion · coverage 추가, 전체 regression 재확인 |
| 원칙 표식 | **폐루프 자동화** · 동일 모델 디버깅 통과율 44% → 94% (NVIDIA 자체 평가, 2026) |

화면: 붉은 점 312개가 네 묶음으로 모인다. 한 묶음이 열리면 두 신호가 같은 cycle에 겹치는 파형이 보인다. 사람이 승인하면 묶음이 풀린다.

### S5-5 Emulation · FPGA (20초)

| 구분 | 자막 |
|---|---|
| 현재 | 최신 RTL과 FW의 뒤늦은 통합, 재현마다 장비 대기 |
| 에이전트 | 매일 최신 RTL + 실제 FW 구동 |
| 문제 | 장시간 부하 중 command timeout |
| 에이전트 | HW 파형 · FW trace 교차 분석 |
| 에이전트 | 원인 가설: 연속 완료 시 interrupt 1건 유실 |
| 에이전트 | 소형 재현 케이스로 축소 |
| 사람 | HW · FW 공동 결정: 완료 전달을 큐 방식으로 |
| 해결 | interface 스펙 개정 · register와 헤더 재생성 |

화면: HW 파형과 FW trace가 위아래로 놓이고 같은 시점에 세로선이 그어진다. 완료 신호 두 개가 비트 하나에 겹쳐 하나가 사라진다. 비트가 큐로 바뀌면 둘 다 전달된다.

### S5-6 FW 개발 (16초)

| 구분 | 자막 |
|---|---|
| 현재 | 초기화 순서 · 사용 조건은 문서와 구두로 전달 |
| 에이전트 | 스펙 변경 시 FW 변경안 제안 |
| 사람 | 불변식 정의: 정정 실패 데이터 반환 금지 |
| 에이전트 | 가상 플랫폼 · 보드에서 빌드 · 실행 · 수정 반복 |
| 사람 | 실제 NAND로 read retry table 확인 · 승인 |

화면: S5-5에서 개정된 스펙이 FW 쪽으로 넘어와 변경안이 된다. 빌드 → 실행 → 수정의 원이 가상 칩 위에서 돈다.

### S5-7 제품 테스트 · 퀄 (28초)

| 구분 | 자막 |
|---|---|
| 현재 | 로그 수동 분석, 막바지 증빙 취합 |
| 에이전트 | 수용 기준에서 시험 항목 파생 |
| 문제 | 고온 방치 후 특정 NAND lot, 지연 기준 초과 |
| 에이전트 | 로그 분류 · 신규 불량 후보 제시 |
| 사람 | NAND 담당의 가설 확인 · FW 반영 결정 |
| 에이전트 | 수정안 비교 · 재시험 범위 초안 |
| 사람 | 범위 승인 · 고객 합의 |
| 강조 | 시험 시간은 그대로, 단축은 원인 분석과 취합 |
| 에이전트 → 사람 | 퀄 패키지 조립 → 판정 · 서명은 사람 |
| 원칙 표식 | **전 과정 추적성** |
| 마무리 | 필드 데이터는 다음 요구사항에 반영 |

화면: 쏟아지는 로그가 묶음으로 정리되고 카드 한 장만 사람 앞으로 온다. 요구사항 카드에 붙은 기록들이 한 줄로 꿰여 퀄 패키지가 되고 사람이 서명한다. 7단계 끝에서 선이 1단계로 돌아가 고리가 닫힌다.

### S6 5대 전환 (18초)

제목 자막: **5대 전환**

| 축 | 현재 | 전환 후 |
|---|---|---|
| 산출물 | 사람용 문서 | 실행 가능한 스펙 |
| 프로세스 | 순차 handoff | 상시 루프 |
| 업무 방식 | 직접 작성 | 의도 정의 · 증거 기반 판단 |
| 시스템 | 개인별 챗봇 | 통합 AI 플랫폼 |
| 문화 | 개인 요령 | 측정 · 공유 · 학습 |

화면: 방금 본 사례의 장면들이 작게 다시 나오며 다섯 축 아래로 정리된다. 요구사항 카드와 interface 스펙은 산출물로, 매일 도는 RTL + FW 구동은 프로세스로 들어간다.

### S9 Closing (14초)

| 역할 | 자막 |
|---|---|
| 설계 | RTL 작성 → 구조 · 계약 결정 |
| 검증 | 테스트 작성 → 기준 정의 · 독립 판정 |
