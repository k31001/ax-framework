> 전략 본문은 `01-strategy.md` 에 있다. 이 문서는 그 전략을 약 3분 영상으로 옮긴 구성안이다.

핵심 메시지는 **"AI 중심 재설계"** 다. S3에서 처음 나오고 S9에서 다시 나온다.

## 2. 자막 문체 원칙

- **명사형으로 끝낸다.** "다시 설계한다"가 아니라 "재설계". 서술형 어미(-습니다, -한다)를 쓰지 않는다.
- **한자어를 한글로 쓴다.** 재설계, 수작업, 대조, 취합, 축적, 상시, 공수. 뜻이 바로 오지 않는 어려운 한자어는 피한다.
- **기술 용어는 영어 그대로.** RTL, PPA, regression, commit, FW, driver, assertion, handoff.
- **한 화면에 문구 하나.** 설명은 화면이 하고, 자막은 이름만 붙인다.
- **전환은 화살표로.** "A → B" 형식으로 현재와 전환 후를 나란히 둔다.

## 4. 씬별 대본

자막은 화면에 나오는 문구 그대로다. 화면 설명은 디자인 안이 정해지면 그 스타일에 맞춰 구체화한다.

### S1 Hook (12초)

| 자막 | 화면 |
|---|---|
| AI 활용, 이미 일상 | 엔지니어 책상 위의 작은 장면들이 하나씩 켜진다 |
| 코드 초안 · 로그 요약 · 스크립트 | 세 가지 작업이 각각 짧게 완료된다 |
| 쉬운 열매는 수확 완료 | 낮은 가지의 열매 몇 개가 사라지고, 나무 전체는 그대로 남는다 |

### S2 문제 (20초)

| 자막 | 화면 |
|---|---|
| 개인 속도 향상, 과제 일정은 제자리 | 7단계 흐름 위에서 점 몇 개가 빠르게 깜빡이지만 전체 길이는 줄지 않는다 |
| 작성 가속 → 병목 이동 | 앞 단계에서 쏟아진 작업이 검증과 통합 앞에 쌓인다 |
| 칩 개발 공수의 60~70%는 검증 | 수치 강조. 출처: Siemens EDA, 2025 |

### S3 전환 선언 (16초)

| 자막 | 화면 |
|---|---|
| AI 도입을 넘어 | 기존 흐름 위에 덧붙인 조각들이 흐려진다 |
| **AI 중심 재설계** | 화면이 비워지고 핵심 메시지가 크게 나온다 |
| 작업 보조 → 워크플로 에이전트 → 프로세스 재설계 | 3단계 계단. 첫 단에 "현재" 표시 |

### S4 5대 전환 (25초)

제목 자막: **5대 전환**

| 축 | 현재 | 전환 후 |
|---|---|---|
| 산출물 | 사람용 문서 | 실행 가능한 스펙 |
| 프로세스 | 순차 handoff | 상시 루프 |
| 업무 방식 | 직접 작성 | 의도 정의 · 증거 기반 판단 |
| 시스템 | 개인별 챗봇 | 통합 AI 플랫폼 |
| 문화 | 개인 요령 | 측정 · 공유 · 학습 |

축마다 약 4.5초. 현재가 먼저 나오고 전환 후로 바뀐다. 다섯 축이 끝나면 한 화면에 모인다.

### S5 전 과정 (60초)

제목 자막: **요구사항부터 퀄까지**

화면 위쪽에 7단계 진행 표시가 계속 떠 있고, 현재 단계가 강조된다. 단계마다 약 8초. 현재를 먼저 보여 주고 전환 후로 넘어간다.

| # | 단계 | 현재 | 전환 후 |
|---|---|---|---|
| 1 | 요구사항 분석 | 문서 수작업 대조 | 변경 영향 자동 추적 |
| 2 | 아키텍처 설계 | 소수 후보, 회의로 결정 | 수백 후보 탐색, 최적점 선택 |
| 3 | IP 설계 · PPA | 스펙 해석 후 RTL 수작업 | 스펙 기반 RTL · assertion 생성, commit마다 PPA 피드백 |
| 4 | 시뮬레이션 검증 | regression 실패 수동 분류 | 상시 검증, 원인 가설 자동 도출 |
| 5 | Emulation · FPGA | 장비 대기, 뒤늦은 HW/FW 통합 | 첫 commit부터 실제 FW 상시 구동 |
| 6 | FW 개발 | 스펙 수작업 반영, 실리콘 대기 | 동일 스펙 기반 driver · 테스트 생성 |
| 7 | 제품 테스트 · 퀄 | 로그 수동 분석, 막바지 증빙 취합 | 신규 불량만 사람에게, 증빙 상시 축적 |

마지막 자막: **필드 이슈는 다음 요구사항에 반영.** 7단계 끝에서 선이 1단계로 돌아가 고리가 닫힌다.

### S6 3대 원칙 (14초)

제목 자막: **3대 원칙**

| 자막 | 화면 |
|---|---|
| 스펙 원본화 | 스펙 하나에서 여러 산출물이 갈라져 나온다 |
| 폐루프 자동화 | 실행 → 결과 → 수정이 원을 그리며 돈다 |
| 동일 모델 디버깅 통과율 44% → 94% | 수치 강조. 출처: NVIDIA 자체 평가, 2026 (모델 단독 → 에이전트 루프) |
| 전 과정 추적성 | 요구사항부터 퀄 증빙까지 한 줄로 꿰인다 |

### S7 책임 (12초)

| 자막 | 화면 |
|---|---|
| **작업은 자동화, 책임은 사람** | 화면이 차분해지고 gate 앞에 사람이 선다 |
| bug 806개 주입 실험: AI는 완료 선언, 최고 모델도 21% 누락 | 수치 강조. 출처: SemiEngineering, 2026-11 |

### S8 로드맵 (14초)

제목 자막: **3단계 로드맵**

| 단계 | 자막 |
|---|---|
| 1 | 기반 구축: 플랫폼 · 데이터 · 기준선 |
| 2 | 병목 우선 에이전트화: 워크플로 단위 폐루프 |
| 3 | 프로세스 재설계: 스펙 중심 흐름 · 역할 전환 |

마지막 자막: **성과는 다음 단계에 재투자.** S1의 열매가 다시 나와 1단계 아래에 심긴다.

### S9 Closing (9초)

| 자막 | 화면 |
|---|---|
| 작성자에서 설계자로 | 사람이 흐름 전체를 내려다보는 자리로 옮겨간다 |
| **AI 중심 재설계** | 핵심 메시지 |
| SSD Controller SoC · AX 전략 | 엔드 카드 |

## 5. 영상에 넣는 수치

세 개 모두 2026-11-10에 원문을 직접 확인했다.

| 씬 | 화면 문구 | 원문 내용 | 출처 |
|---|---|---|---|
| S2 | 칩 개발 공수의 60~70%는 검증 | "60–70% of engineering effort in chip projects belongs in verification" | Siemens EDA 블로그 (Harry Foster), 2025-09-03 |
| S6 | 동일 모델 디버깅 통과율 44% → 94% | CVDP 디버깅 항목에서 한 모델이 단독 44.0%, 에이전트와 함께 94.3% | NVIDIA Technical Blog, 2026-07-26 (자체 평가) |
| S7 | bug 806개 주입, 최고 모델도 21% 누락 | 설계 25개에 bug 806개를 심었고 최고 모델이 20.8%를 누락. 세 모델 모두 자체 목표 100% 달성 후 sign-off 선언 | SemiEngineering, 2026-11-02 |

S7의 "작업은 자동화, 책임은 사람"은 같은 기사에 인용된 Arm 소속 엔지니어의 말("You can automate the work of verification. You cannot automate the responsibility for it.")을 줄여 옮긴 것이다.
